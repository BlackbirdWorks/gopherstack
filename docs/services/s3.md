# S3

In-memory S3 with versioning, multipart upload, Object Lock, replication, bucket configuration APIs and S3 Select. Data lives in memory; with `--persist` it survives restarts.

## Quick start

```bash
export AWS_ENDPOINT_URL=http://localhost:8000
aws s3api create-bucket --bucket my-bucket
aws s3 cp file.txt s3://my-bucket/
aws s3 ls s3://my-bucket/
aws s3api put-bucket-versioning --bucket my-bucket \
    --versioning-configuration Status=Enabled
aws s3api put-object --bucket my-bucket --key f.txt --body file.txt \
    --tagging "env=dev&project=myapp"
```

Create buckets at startup with `--s3-bucket a,b` (env `S3_BUCKETS`).

## Supported operations

| Area | Operations |
|------|------------|
| Buckets | `CreateBucket`, `DeleteBucket`, `ListBuckets`, `HeadBucket`, `GetBucketLocation`, `ListDirectoryBuckets` |
| Objects | `PutObject`, `GetObject`, `HeadObject`, `DeleteObject`, `DeleteObjects`, `CopyObject`, `RenameObject`, `RestoreObject`, `PostObject`, `GetObjectAttributes`, `GetObjectTorrent`, `SelectObjectContent` |
| Listing | `ListObjects`, `ListObjectsV2`, `ListObjectVersions` |
| Multipart | `CreateMultipartUpload`, `UploadPart`, `UploadPartCopy`, `CompleteMultipartUpload`, `AbortMultipartUpload`, `ListMultipartUploads`, `ListParts` |
| Versioning | `Get/PutBucketVersioning` |
| Tagging | `Get/Put/DeleteBucketTagging`, `Get/Put/DeleteObjectTagging` |
| ACL and policy | `Get/PutBucketAcl`, `Get/PutObjectAcl`, `Get/Put/DeleteBucketPolicy`, `GetBucketPolicyStatus`, `Get/Put/DeletePublicAccessBlock`, `Get/Put/DeleteBucketOwnershipControls` |
| CORS, lifecycle, website | `Get/Put/DeleteBucketCors`, `Get/PutBucketLifecycleConfiguration`, `DeleteBucketLifecycle`, `Get/Put/DeleteBucketWebsite` |
| Encryption | `Get/Put/DeleteBucketEncryption`, `UpdateObjectEncryption` |
| Object Lock | `Get/PutObjectLockConfiguration`, `Get/PutObjectRetention`, `Get/PutObjectLegalHold` |
| Notification, logging, replication | `Get/PutBucketNotificationConfiguration`, `Get/PutBucketLogging`, `Get/Put/DeleteBucketReplication` |
| Analytics, inventory, metrics, tiering | `Put/Get/Delete/ListBucket{Analytics,Inventory,Metrics,IntelligentTiering}Configuration` |
| Misc bucket settings | `Get/PutBucketAccelerateConfiguration`, `Get/PutBucketRequestPayment`, `Get/PutBucketAbac` |
| Metadata tables | `Create/Get/DeleteBucketMetadataConfiguration`, `Create/Get/DeleteBucketMetadataTableConfiguration`, `UpdateBucketMetadata{Inventory,Journal,Annotation}TableConfiguration` |
| Annotations | `Put/Get/Delete/ListObjectAnnotation(s)` |
| Express One Zone, Object Lambda | `CreateSession`, `WriteGetObjectResponse` |

Presigned URLs work with the SDK's presigners.

## Configuration

| Flag / env | Default | Purpose |
|------------|---------|---------|
| `--s3-bucket` / `S3_BUCKETS` | none | Buckets created at startup |
| `S3_REGION` | `us-east-1` | Default region |
| `S3_JANITOR_INTERVAL` | `500ms` | Background janitor tick |
| `S3_COMPRESSION_MIN_BYTES` | `1024` | Minimum object size for zstd compression; `0` compresses everything |
| `GOPHERSTACK_S3_VALIDATE_SIGNATURES` | off | Verify S3 request and presigned-URL signatures against `--sigv4-secret` |
| `GOPHERSTACK_S3_SKIP_KMS_KEY_VALIDATION` | off | Accept SSE-KMS key IDs that do not exist in the KMS emulator |
| `GOPHERSTACK_S3_DISABLE_CUSTOM_CORS` | off | Ignore per-bucket CORS rules |

Objects are compressed in memory (zstd; gzip blobs from older snapshots still decode). Clients do not see this.

## Differences from AWS

> [!WARNING]
> `x-amz-mfa` is not validated. With MFA Delete enabled a missing token is `AccessDenied`, but any token value is accepted.

- Bucket policy and ACL checks cover object requests. Explicit `Deny` always applies. Anonymous and public-ACL gating applies only when authorization enforcement is on.
- `XXHASH64`, `XXHASH3` and `XXHASH128` checksums are not modelled.
- Replication and per-storage-class request metrics, and `SelectRequests`/`SelectBytes*` metrics, are not produced.
- `CreateBucket` `x-amz-bucket-namespace` and `PutBucketPolicy` `x-amz-confirm-remove-self-bucket-access` are not evaluated.
- `ListDirectoryBuckets` through a custom endpoint needs `DisableS3ExpressSessionAuth = true` in the SDK client.
