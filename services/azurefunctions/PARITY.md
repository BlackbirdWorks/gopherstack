## Emulator choices where the vendor is silent

- A host start is triggered at deploy when application code registers a non-HTTP trigger: Node v4 `app.timer(`, `app.storageQueue(` and the other registration methods (Learn: Azure Functions Node.js developer guide), Python v2 `@app.timer_trigger` and the like (Learn: Python developer guide), or a compiled .NET assembly carrying a trigger attribute type name; Azure's scale controller learns these from the host, which the emulator cannot ask without starting it.
- A failed remote build answers 500 with the build log; Kudu's status code for it is not documented.
- POST /api/command with no dir runs in /home/site/wwwroot; Learn does not state the default directory.
- The vfs skeleton below /home lists only LogFiles, data and site; Learn does not list what a fresh app's /home holds.
- The Kudu REST API wiki documents only the request of POST /api/command; the emulator answers Output, Error and ExitCode, which is how Kudu's CommandController answers, and runs with no dir in /home/site/wwwroot.
- /api/vfs list entries (name, size, mtime, crtime, mime, href, path), the status codes of vfs PUT and DELETE and the shape of /api/deployments/{id}/log entries (log_time, id, message, type, details_url) are not on the wiki; they follow Kudu's JSON.
- POST /api/triggeredwebjobs/{name}/run answers 202 Accepted; the wiki shows only the Location header.
- /MSI/token answers 401 for a missing or wrong X-IDENTITY-HEADER and 400 with {statusCode, message} for the other errors; Learn documents only the 200 response.
- Slot-limit and swap-conflict errors are 409 Conflict, diffRule and description strings in slotsdiffs are the emulator's own wording, and keys, Kudu deployment history and the publishing password stay with their slot on a swap; Learn documents none of these.
- Hosts of apps that have a managed identity are restarted when the identity changes (Learn: "After you finish these steps, the app restarts" for user-assigned identities).
- Windows function apps and runtime versions other than ~4 run in the same Linux v4 images: learn.microsoft.com/en-us/azure/azure-functions/functions-versions says only the 4.x host is supported (1.x ended 2026-09-14, 2.x and 3.x are out of support), and Windows hosts need a Windows kernel the emulator does not have.
- Service Bus and Event Hubs connection strings need an explicit port and UseDevelopmentEmulator=true because the emulator's AMQP listeners are plaintext on non-default ports; learn.microsoft.com/en-us/azure/service-bus-messaging/test-locally-with-service-bus-emulator documents UseDevelopmentEmulator=true, a plaintext port 5672 and host.docker.internal or the host IP for containers on another network. The container-reachable address follows the Lambda and RDS convention (LAMBDA_DOCKER_HOST, 172.17.0.1, host.docker.internal) and was not run on Kubernetes.
