## Notes

Protocol is awsjson1.1 with target prefix `ServiceQuotasV20190624.`; timestamps are epoch-seconds numbers (`awstime.Epoch`). Shapes come from the pinned SDK schemas and types.

Emulator choices the SDK does not document:

- Applied quota values are per account and Region; an approved request stores the desired value as the applied override.
- A request needs DesiredValue above the current applied value; a quota that is not adjustable is IllegalArgumentException.
- Auto management is evaluated by a one-minute ticker (`Handler.SetTickInterval`); each quota notifies once per threshold crossing (80%, then 95%) and re-arms after utilization falls below 80%.
- Utilization usage and enforcement limits are read through `UsageSource` and `quotalimit.Func` wired in `internal/app/service_quotas_wiring.go`; enforcement of the owning services applies the default or approved value of the caller account and Region.
- Template operations need an organization with all features and service access for `servicequotas.amazonaws.com` enabled, wired from the Organizations backend; a standalone backend without a directory reports NoAvailableOrganizationException.
- Get, List and Delete on template entries do not require an association; only Disassociate does.
- Tag ARNs must name a catalogued quota of the caller account and Region.
- Associating the template files its requests in accounts created in the organization afterwards (organization-templates.html: "Whenever new accounts are created in your organization, the template automatically requests quota increases"; existing accounts are not updated); invited accounts that join are not documented as receiving them and get none. Requests are filed once, at creation, with the management account root as requester.

## 2026-11-13 template limits

Quota request templates answer TemplatesNotAvailableInRegionException in opt-in, China and GovCloud Regions and hold at most 10 items (QuotaExceededException on the 11th); sources docs.aws.amazon.com/servicequotas/latest/userguide/organization-templates.html and docs.aws.amazon.com/accounts/latest/reference/manage-acct-regions.html.

## Live usage and enforcement

- Count quotas are classified one by one in `internal/app/testdata/service_quota_classes.json` (c counted, e count without counter, s size or length, r rate or concurrency); `TestQuotaClassificationCoversCatalog` fails for a catalogued quota missing from it and `TestQuotaCountersMatchClassification` for a counter and a class that disagree. The s/r/e split of the uncounted quotas is name-derived and was not reviewed quota by quota.
- Quotas scoped to a parent (subnets per VPC, rules per security group, aliases per KMS key, rules per event bus, routes per table, versions and aliases per state machine) report the largest count in any single parent in the Region, and enforce per parent.
- Enforcement reads the applied value before the owning backend takes its lock and compares it inside the same critical section as the create, so concurrent creates cannot overshoot; with the flag off nothing is consulted and the built-in caps (EventBridge 200 buses and 300 rules per bus, KMS 50,000 grants per key, EFS file system cap) are unchanged.
- Limit errors come from the SDK operation error lists (`deserializeOpError<Op>` of the pinned module versions) or, for EC2, from the EC2 error code reference (NatGatewayLimitExceeded, NetworkInterfaceLimitExceeded, ResourceCountLimitExceeded).
- EC2 vCPU quotas count pending and running On-Demand instances by instance family class and open or active Spot requests by requested type; instances launched by a Spot request are excluded from the On-Demand count.
- Route 53 is account-global: it consults the applied value of the Service Quotas backend's own account and Region.
- Rate, throughput and concurrency quotas (requests per second, concurrent executions) are catalogued with their values and never produce throttling; no usage is reported for them.

## Primary-source checks (2026-11-13)
- servicequotas: IAM reference_iam-quotas.html lists the maximum quotas per account as roles 10,000, customer managed policies 10,000, instance profiles 10,000 and groups 500 (catalog fixed from 5,000).

## Emulator choices where the vendor is silent

- Catalog: quotas without a documented code are absent (the General Reference prints codes only for adjustable quotas; SQS and SNS print none), and docs defaults that vary by Region use the Region-independent value, else us-east-1; codes are not verified against the live API.
- AutoManagement NotifyAndAdjust sends the 95% notification only; automatic-management.html states neither the requested value nor which quotas qualify for automatic approval, so no automatic request is filed.
- Errors AccessDenied (non-template operations), DependencyAccessDenied, TagPolicyViolation, TooManyRequests and ServiceException are not raised: they have no emulated cause (IAM evaluation is a separate setting).
- Resource-level quotas are not modelled and ContextId is rejected with IllegalArgumentException. The only documented resource-level quota is OpenSearch (es) 'Instances per domain' (request-quota-increase.html); the docs publish no list of resource-level quotas, no ContextScopeType values and no ARN pattern per quota, so INVALID_REQUEST (invalid ContextId ARN) cannot be decided from a source (quotas.go:70 checkContext).

## External effects that are recorded, not performed

- Support staff review: a request approves on the lifecycle dwell unless its Support case is resolved first (CASE_CLOSED). DENIED is entered only for desired values above the catalogued hard max; NOT_APPROVED is never entered because no reviewer exists.
