## Notes

Protocol is REST-JSON (`pkgs/restroute`): every operation is a POST to `/<OperationName>` except the tag operations on `/tags/{resourceArn}`. Timestamps are ISO8601 `date-time` strings because the schemas carry an explicit `timestampFormat`, unlike the JSON-protocol services. Requests are matched by the `resource-explorer-2` SigV4 signing name or the SDK user-agent marker.

Emulator choices the SDK does not document:

- One index per Region and account; a view needs it. Deleting the index deletes the Region's views.
- Resources with an empty ARN Region (S3) take the Region of the query; IAM, Route 53, CloudFront, Organizations, WAF, Shield, Global Accelerator, Network Manager and STS resources report the Region `global`.
- A caller whose account differs from the resource ARN account sees nothing.
- Search results are ordered by ARN; NextToken is an offset token validated by `pkgs/page`.

## 2026-11-13 query syntax and page limits

Verified against docs.aws.amazon.com/resource-explorer (using-search-query-syntax.html, API_ListViews/Search/ListIndexes/ListSupportedResourceTypes/ListResources/ListManagedViews/ListIndexesForMembers): MaxResults maxima are ListViews 50, ListManagedViews 50, Search/ListResources/ListSupportedResourceTypes 1000, ListIndexes 100, ListIndexesForMembers 10. Keywords are OR-ed word matches ranked by hit count, filters AND-ed with comma OR values, quotes make phrases, backslash escapes, trailing `*` prefixes, application filter by name or group ARN, tag/application filters need a tags view, FilterString takes filters only. The managed view policy follows the documented two-statement shape.

## Emulator choices where the vendor is silent

- ListSupportedResourceTypes: the supported-resource-types page (resource-explorer userguide supported-resource-types.html) and the CLI example in it carry only Service and ResourceType, no CloudFormation column, so CFNResourceTypes is filled only for the 48 curated rows whose mapping the emulator knows; every documented type is listed whether or not an emulated service can produce it, as the real API lists a global catalogue
- resourcetype.supports:tags: the user guide defines it as "only the resources that are taggable" but publishes no per-type catalogue; every resource the emulator enumerates comes from a service wired into the tagging aggregation, so it matches all of them and any other value matches none
- ListIndexesForMembers: with Organizations wired, a caller outside the management account or a delegated administrator with service access gets AccessDeniedException (API_ListIndexesForMembers.html); a caller in no organization, and listed accounts that are not organization members, are choices the page does not describe (denied, and skipped silently)
- CreateView scope: an organization or OU ARN is checked against Organizations when it is wired, otherwise accepted; a missing one is ValidationException (CreateView declares ValidationException, API_CreateView.html)

- GetManagedView: the two managed view names (AWSDefaultViewForSystemsManager, AWSDefaultViewForResilienceHub) and their ARN UUIDs are emulator-defined; the user guide (aws-managed-views.html) names only the Systems Manager unified-console view as AWSManagedViewForSSM and publishes no ARN
- ConflictException: several conflict and validation cases (view without an index, aggregator rules, duplicate type update) use codes chosen from documented behaviour, not from SDK evidence
