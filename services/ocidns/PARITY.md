## Verified against Oracle documentation

- Duplicate zone, TSIG key, resolver endpoint and steering policy attachment creates return 409 NotAuthorizedOrResourceAlreadyExists, which the common errors page says is returned only from create operations: https://docs.oracle.com/en-us/iaas/Content/API/References/apierrors.htm.
- CreateZoneFromZoneFile now remembers its opc-retry-token.

## Primary-source checks (2026-11-13)
- ocidns: RecordOperation SDK comment confirms an ADD with a ttl sets the TTL for every record of the RRSet (retiming) and defines REQUIRE and PROHIBIT as preconditions.

## Emulator choices where the vendor is silent

- Not published (checked DNS dnszonemanagement.htm and the dns SDK comments): 202 for creates and compartment moves; 409 Conflict for the remaining non-create conflicts; 412 PreconditionFailed for failed REQUIRE and PROHIBIT; 400 InvalidParameter for CNAME, ALIAS and apex violations; GLOBAL as the default scope for lookups and lists; 404 for an empty domain or record set; the SOA rdata, the SOA ttl of 300, the NS ttl of 86400, the four ns1 to ns4.p68.dns.oraclecloud.net nameservers; the recordHash algorithm; OCID prefixes; the 192.0.2.53 and .54 transfer servers.
- TSIG keys with algorithm hmac-sha1 are accepted and stored (the SDK lists it) but never sign or verify: crypto/sha1 is barred by test/guards/weak_hash_guard_test.go, so a transfer or NOTIFY naming such a key fails with a logged error.
- Record types beyond the supported list, DNSSEC types and non-apex SOA are refused; rdata is validated and normalised by the DNS library, which may differ from Oracle's presentation.
- Zone version history keeps the last 20 versions of a zone's user records; older versions answer 404. The apex SOA and NS of an earlier version are shown as they are now.
- Steering: weights of 0 or without a matching answerData sort after weighted answers; answers without a priority value go last (Traffic Management page); a FILTER rule with answerData drops answers that match none of it; geoKey and asn conditions never match because the emulator has no client geolocation database; a policy that filters out every answer answers NODATA. Expressions are limited to one comparison (no and/or: the page documents none) and 1024 characters.
- CREATING, UPDATING and DELETING states are not modelled (every change is immediate and resources are ACTIVE); the DNS SDK exposes no work-request read operation; opc-retry-token on the compartment moves is idempotent by construction; quotas are not modelled.
- Unicode zone names are converted to punycode (SDK CreateZoneDetails.Name, RFC 3492); record owner names and rdata must already be ASCII.

## External effects that are recorded, not performed

- HEALTH steering rules and healthCheckMonitorId: there is no Health Checks service in this emulator, so a HEALTH rule keeps every answer and healthCheckMonitorId is stored without being resolved.
- ALIAS targets outside the GLOBAL zones of this emulator are not resolved (no recursion), so those names answer NODATA.
