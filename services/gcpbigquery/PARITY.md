Initial implementation (2026-10-19): REST v2 datasets, tables, tabledata, jobs and jobs.query verified against cloud.google.com/go/bigquery v1.85.0 through the official client in the package tests (dataset and table lifecycle, streaming inserts with de-duplication, parameterised queries, nested and repeated round trips, load/extract/copy including Parquet, DML and DDL, paging). The GCS hooks are exercised against the real GCS emulator in internal/app. Wire shapes were read from google.golang.org/api/bigquery/v2 and the client's value decoder (TIMESTAMP is integer microseconds under useInt64Timestamp); behaviour of the live service was not available for comparison.

Pass 2026-11-13: ARRAY_AGG ... LIMIT, named WINDOW clauses (OVER w, OVER (w ...), WINDOW a AS (b ...)), INTERSECT/EXCEPT ALL, APPROX_QUANTILES (offset floor(i*(N-1)/number); every example on https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/approximate_aggregate_functions reproduces) and APPROX_TOP_COUNT (exact counts, ties by value, NULL counted) are implemented in the engine. Tables past expirationTime read as deleted and dataset defaultTableExpirationMs sets expirationTime on new tables (https://docs.cloud.google.com/bigquery/docs/reference/rest/v2/datasets). jobs.query requestId (at most 36 characters) replays the earlier job for 15 minutes (https://docs.cloud.google.com/bigquery/docs/reference/rest/v2/jobs/query); Job snapshots gained requestId.

## Emulator choices where the vendor is silent

- Partition and cluster pruning is not performed: queries scan the whole in-memory table and report totalBytesProcessed 0.
- TABLESAMPLE SYSTEM keeps each row independently with probability percent/100; BigQuery samples storage blocks.
- The streaming buffer drains 90 minutes after its oldest entry (https://docs.cloud.google.com/bigquery/docs/streaming-data-into-bigquery) and numRows still counts buffered rows.
- A script stops with an error after 1,000,000 executed statements or loop iterations instead of running until a timeout.
- EXECUTE IMMEDIATE does not see script variables; values reach the dynamic statement through USING.
- SET and DECLARE ... DEFAULT cast the value to the variable's declared type with CAST, which accepts conversions BigQuery's assignment coercion would reject.
- A recursive CTE fails with "Recursive CTE iteration limit of 500 exceeded"; the limit comes from the engine, the message is ours.
- @@error is read as the named parameter @error inside an exception handler, so a user parameter called error is shadowed there.
- A procedure's definitionBody is the BEGIN ... END text as written.
- Transactions snapshot every dataset on BEGIN and restore it on ROLLBACK; concurrent requests are serialised by the backend lock, so isolation is trivial.
- A materialized view is evaluated live; enableRefresh and refreshIntervalMs are stored and returned but nothing refreshes on a schedule.
- Time-travel history keeps at most 64 versions per table, and writes in the same millisecond share one version.

Pass 2026-11-14: row access policies per https://docs.cloud.google.com/bigquery/docs/managing-row-level-security and https://docs.cloud.google.com/bigquery/docs/row-level-security-intro (union of matching policies, no rows for non-grantees, tabledata.list on a protected table refused, CREATE OR REPLACE TABLE and load WRITE_TRUNCATE drop policies, a column a policy reads cannot be dropped). External tables per https://docs.cloud.google.com/bigquery/docs/hive-partitioned-queries and the CREATE EXTERNAL TABLE reference. NET.* examples reproduce https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/net_functions; FARM_FINGERPRINT implements FarmHash Fingerprint64 and reproduces the hash_functions examples plus the upstream FarmHash test strings up to 90 bytes; INTERVAL, JUSTIFY_*, MAKE_INTERVAL and interval operators reproduce the interval_functions and operators examples; ST_* follow the geography_functions page; SEARCH and TEXT_ANALYZE follow search_functions and text-analysis; script CASE follows the procedural-language page; reservations follow google.golang.org/api/bigqueryreservation/v1.

## Emulator choices where the vendor is silent (additions)

- Group grantees never match a caller because group membership is unknown; domain: matches the caller's email domain.
- Row access policy filters are evaluated per row with NULL treated as FALSE; DML and extract ignore policies; tabledata.list on a protected table is 403 accessDenied.
- Dropping the last row access policy without DROP ALL or force is 400 with the emulator's own message.
- HLL_COUNT sketches use the emulator's own byte layout (sparse 25-bit then dense registers) and a raw HyperLogLog estimate without BigQuery's bias tables; they are not byte-compatible with BigQuery sketches.
- Spherical Earth radius is 6371010 m (S2); ST_ASGEOJSON writes `{ "type": "Point", "coordinates": [x, y] }`; ST_GEOGFROMTEXT ignores planar and rejects make_valid; polygon containment treats the smaller side of a ring as the interior.
- NO_OP_ANALYZER matches case-sensitively and exactly.
- Interval equality and ordering treat a month as 30 days and a day as 24 hours; EXTRACT from an interval returns INT64 as the examples show.
- Reservation scheduling is not simulated; capacity commitment ends are start plus the plan period (FLEX one minute) and FAILED_PRECONDITION is HTTP 400.
- Script CASE evaluates the search expression once per WHEN; no match without ELSE runs nothing.
- External table partition values equal to __HIVE_DEFAULT_PARTITION__ read as NULL; files are re-read on every query.
- Extract destination URIs follow docs.cloud.google.com/bigquery/docs/exporting-data: at most one wildcard per URI, only in the file name, replaced by a 12-digit shard number; violations fail the job as invalid.

Partitioning: PARTITION BY maps onto timePartitioning (DATE column, DATE(ts), DATE_TRUNC, DATETIME_TRUNC, TIMESTAMP_TRUNC, _PARTITIONDATE) or rangePartitioning (RANGE_BUCKET with GENERATE_ARRAY) and CLUSTER BY onto clustering.fields, with the documented "PARTITION BY expression must be ..." error; require_partition_filter and requirePartitionFilter make a query without a top-level predicate over the partition column fail (https://docs.cloud.google.com/bigquery/docs/querying-partitioned-tables). TABLESAMPLE SYSTEM (percent PERCENT) per https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/query-syntax. Tables report streamingBuffer after insertAll (Table.streamingBuffer in the REST reference).
