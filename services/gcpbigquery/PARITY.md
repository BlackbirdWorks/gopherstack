## Emulator choices where the vendor is silent

- Partition and cluster pruning is not performed: queries scan the whole in-memory table and report totalBytesProcessed 0.
- TABLESAMPLE SYSTEM keeps each row independently with probability percent/100; BigQuery samples storage blocks.
- - The int64 overflow error text is "int64 overflow: a + b"; the operators page only says operators throw on overflow.
- An untyped NULL selected as a column is INT64 (data types, literals), as is the element type of an empty array literal.
- Extract shards at 1 GiB of logical bytes and, with several destination URIs, deals shards to the URIs in turn; the exporting-data page does not say how rows are split between URIs. A URI without a wildcard holds one file and a larger table is an error.
- A load job with maxBadRecords skips bad rows, counts them in statistics.load.badRecords and lists the first five in status.errors.
- Unfinished jobs are not resumed after a restart; they finish as stopped.
- The jobTimeoutMs error and the cancellation message are the emulator's wording.
- SAFE_CAST ... FORMAT returns NULL for an invalid format string or time zone as well as for invalid input; the format-elements page only documents NULL for input that does not match.
- CAST ... FORMAT ignores AT TIME ZONE for DATE, TIME and DATETIME targets and rejects day 0, year 0 and TZH above 14 or TZM above 59; the page does not state these ranges.
- A load append matches columns by name case-insensitively, recurses into RECORD fields, and treats any mode change other than REQUIRED to NULLABLE (with ALLOW_FIELD_RELAXATION) as a schema mismatch.
- CAST ... FORMAT with TZH/TZM and no AT TIME ZONE uses UTC; without year or month, parsing fills the current UTC year and month (format-elements page).
- The streaming buffer drains 90 minutes after its oldest entry (https://docs.cloud.google.com/bigquery/docs/streaming-data-into-bigquery) and numRows still counts buffered rows.
- A script stops with an error after 1,000,000 executed statements or loop iterations instead of running until a timeout.
- EXECUTE IMMEDIATE does not see script variables; values reach the dynamic statement through USING.
- SET and DECLARE ... DEFAULT cast the value to the variable's declared type with CAST, which accepts conversions BigQuery's assignment coercion would reject.
- A recursive CTE fails with "Recursive CTE iteration limit of 500 exceeded"; the limit comes from the engine, the message is ours.
- @@error is read as the named parameter @error inside an exception handler, so a user parameter called error is shadowed there.
- A procedure's definitionBody is the BEGIN ... END text as written.
- Transactions snapshot every dataset on BEGIN and restore it on ROLLBACK; concurrent requests are serialised by the backend lock, so isolation is trivial.
- A materialized view is evaluated live; enableRefresh and refreshIntervalMs are stored and returned but nothing refreshes on a schedule.
- Time-travel history keeps at most 64 versions per table, and writes in the same millisecond share one version.

## Emulator choices where the vendor is silent (additions)

- An extract job with more than 500 destinationUris is 400 invalid: quotas page documents 500 wildcard URIs per extract job and states no limit on destinationUris, so the emulator applies 500 to every URI.
- Group grantees never match a caller because group membership is unknown; domain: matches the caller's email domain.
- Row access policy filters are evaluated per row with NULL treated as FALSE; DML and extract ignore policies; tabledata.list on a protected table is 403 accessDenied.
- Dropping the last row access policy without DROP ALL or force is 400 with the emulator's own message.
- HLL_COUNT sketches use the emulator's own byte layout (sparse 25-bit then dense registers) and a raw HyperLogLog estimate without BigQuery's bias tables; they are not byte-compatible with BigQuery sketches.
- Spherical Earth radius is 6371010 m (S2); ST_ASGEOJSON writes `{ "type": "Point", "coordinates": [x, y] }`; ST_GEOGFROMTEXT ignores planar and rejects make_valid; polygon containment treats the smaller side of a ring as the interior.
- NO_OP_ANALYZER matches case-sensitively and exactly.
- Interval equality and ordering treat a month as 30 days and a day as 24 hours; EXTRACT from an interval returns INT64 as the examples show.
- Reservation scheduling is not simulated; capacity commitment ends are start plus the plan period (FLEX one minute) and FAILED_PRECONDITION is HTTP 400.
- Script CASE evaluates the search expression once per WHEN; no match without ELSE runs nothing.
- External table partition values equal to __HIVE_DEFAULT_PARTITION__ read as NULL; files are re-read on every query.
- ST_MAKELINE cuts overlapping edges at each other's vertices, merges them, and walks lines from the lowest-numbered odd-degree vertex taking the lowest-numbered unused neighbour first; a simple retrace A B A gives LINESTRING(A B). The page documents only the MULTILINESTRING example, not vertex order or chaining. A self-crossing line without overlap is unchanged. An edge spanning exactly 180 degrees (antipodal points) is rejected.
- Extract destination URIs follow docs.cloud.google.com/bigquery/docs/exporting-data: at most one wildcard per URI, only in the file name, replaced by a 12-digit shard number; violations fail the job as invalid.

ST_MAKELINE nodes retraced and overlapping edges into the documented MULTILINESTRING (example `MULTILINESTRING((1 0, 5 0, 10 0), (5 0, 5 4))`); SEARCH reads AND/OR inside a double-quoted phrase as logical operators (documented example `SEARCH(R'foo bar', R'"foo AND (bar OR baz)"')` is TRUE).

Partitioning: PARTITION BY maps onto timePartitioning (DATE column, DATE(ts), DATE_TRUNC, DATETIME_TRUNC, TIMESTAMP_TRUNC, _PARTITIONDATE) or rangePartitioning (RANGE_BUCKET with GENERATE_ARRAY) and CLUSTER BY onto clustering.fields, with the documented "PARTITION BY expression must be ..." error; require_partition_filter and requirePartitionFilter make a query without a top-level predicate over the partition column fail (https://docs.cloud.google.com/bigquery/docs/querying-partitioned-tables). TABLESAMPLE SYSTEM (percent PERCENT) per https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/query-syntax. Tables report streamingBuffer after insertAll (Table.streamingBuffer in the REST reference).

Pass 2026-11-21: NUMERIC and BIGNUMERIC are exact decimals end to end (bqsql/decimal.go, decimal_math.go, decimal_format.go, udf_decimal.go, compile_decimal.go). Values are math/big scaled integers; inside SQLite they are '#' plus 64 hex digits of value*10^38+2^255, so `=`, DISTINCT, GROUP BY, JOIN keys, ORDER BY, MIN, MAX and comparisons are plain text operations and equal values encode alike for both kinds, while the kind travels in the compiled expression type. The compiler coerces INT64 and literal FLOAT64 operands to the decimal kind (data-type coercion table and literal coercion in https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/conversion_rules, read through a page summary) in operators, comparisons, CASE, IF, COALESCE, IFNULL, NULLIF, IN, BETWEEN, UNION and the other set operators, array and struct literals, DML targets and routine arguments; NUMERIC with BIGNUMERIC is BIGNUMERIC, anything with a non-literal FLOAT64 is FLOAT64. ABS, SIGN, CEIL, FLOOR, ROUND (with ROUND_HALF_AWAY_FROM_ZERO and ROUND_HALF_EVEN), TRUNC, MOD, DIV, POW, SQRT, EXP, LN, LOG, LOG10, SAFE_ADD, SAFE_SUBTRACT, SAFE_MULTIPLY, SAFE_DIVIDE, SAFE_NEGATE, GREATEST, LEAST and GENERATE_ARRAY return NUMERIC or BIGNUMERIC per the mathematical functions page (summary). SUM and AVG return the input type through aggregate and window callbacks; VARIANCE and STDDEV keep exact power sums and convert the result to FLOAT64 (statistical aggregate page summary); MIN, MAX, ANY_VALUE, ARRAY_AGG, COUNT(DISTINCT) and LAG/LEAD work on the encoding. CAST and SAFE_CAST between INT64, FLOAT64, STRING, NUMERIC and BIGNUMERIC, PARSE_NUMERIC and PARSE_BIGNUMERIC (commas before the point, one sign before or after, whitespace around, exponent), NUMERIC(P[, S]) and BIGNUMERIC(P[, S]) on CAST, DDL, insertAll, load and DML (round to S, error past P), FORMAT %f %e %g %t %T and TO_JSON_STRING work on exact digits. Avro decimal load keeps all 38 BIGNUMERIC digits and Parquet, CSV, NDJSON and insertAll parse the decimal text. Stored rows and snapshots keep the canonical decimal string, so old snapshots restore unchanged and Restore rewrites every NUMERIC cell through the canonical parser.

## Emulator choices where the vendor is silent (NUMERIC)

- Overflow errors read "numeric overflow: a + b" and "BIGNUMERIC overflow: a + b", division by zero "division by zero: a / b", and the other decimal errors carry the emulator's wording; the pages only say the operation errors.
- POW, EXP, LN, LOG, LOG10 and SQRT of decimals are evaluated at 640 bits (exact for integer exponents up to 256) and rounded half away from zero to the result scale; the functions page gives result types, not an algorithm.
- CAST of NUMERIC to INT64 rounds half away from zero; the conversion page does not describe it. AVG of NUMERIC rounds half away from zero at the result scale.
- FORMAT %f, %e and %g of NUMERIC print exact digits with ties away from zero; %t prints a whole value with ".0" and %T as NUMERIC "1.25" or BIGNUMERIC "1.25" as the format table shows.
- A NUMERIC literal or string with more fraction digits than the scale rounds half away from zero, as CAST of STRING does.
- Parameterised NUMERIC(P, S) values on insertAll, load and DML are rounded to S and fail with the emulator's message when more than P digits remain.
- HLL_COUNT.INIT hashes the decimal's internal encoding, so NUMERIC and BIGNUMERIC sketches of equal values agree with each other, not with BigQuery.
