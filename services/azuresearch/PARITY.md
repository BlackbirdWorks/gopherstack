## Notes

Evidence: Azure AI Search REST (data plane 2024-07-01, management 2025-05-01 as pinned by armsearch v1.4.0) and learn.microsoft.com/azure/search pages on vector ranking (cosine range 0.333 to 1.0, score = 1/(1+cosine distance)) and hybrid RRF (1/(rank+60), vector weight as multiplier), consulted 2026-11-05. Anything marked unverified above was written from recollection.

The data plane is multi-tenant: one listener (default 10015) serves every service created through ARM. ARM advertises `https://{name}.search.<host>:<port>`; the host label selects the service, so `{name}.search.windows.net` resolves too when DNS points at the listener.

## Emulator choices where the vendor is silent

- No Go data-plane SDK exists, so the data plane is verified against documented REST shapes only; error message texts, the 403 body, the index-exists status (400 here; the Create Index reference lists only 201 and a generic ErrorResponse) and null ordering in $orderby are not documented anywhere fetched.
- HNSW is an exact scan: no approximate recall behaviour and no efSearch effect; the euclidean, dotProduct and hamming score formulas are not documented (the vector relevance page documents only cosine, which matches).
- Scoring-function boost arithmetic and BM25 multi-field combination (sum of per-field scores) follow the documented parameters, but the docs give no formulas, so they are not verified against the service.
- Debug subscores report the BM25 score after scoring-profile boosts as the text searchScore, and documentBoost is the scoring-profile function boost (1 without a profile).
- vectorSimilarity thresholds apply to the canonical metric (cosine similarity, dot product, euclidean distance, hamming squared difference) before the top k cut; euclidean and hamming keep values at or below the threshold. The spec says only that direction follows the metric.
- Scalar quantization maps each stored vector onto 256 levels between its own minimum and maximum, binary quantization keeps the sign of each component; the service's quantizer is not documented.
- A concurrent indexer run or reset answers 409 Conflict; the REST reference lists only 202 and 204.
- Without --azure-search-validate-tokens every bearer token is an administrator, matching the other emulated Azure data planes.
- A run holds the backend lock while it applies documents, so requests made during the run queue behind it; inProgress is visible from the moment search.run returns until the run executes.
- Upgrade always succeeds and stamps serviceUpgradedAt; the emulator never reports upgradeAvailable=available.
- encryptionComplianceStatus is NonCompliant for one or more unencrypted objects when enforcement is Enabled; the SDK doc says both "more than one" and "one or more".
- Azure SQL rows are keyed by their first column and change-tracked by a hash of the row; the query interface returns text, so target field types coerce from strings.
- The word_delimiter family emits every part at the original token's position.
- Snowball stemmers stand in for Lucene's language-specific light stemmers.
