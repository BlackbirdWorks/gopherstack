## Emulator choices where the vendor is silent

- The one-minor-ahead control plane upgrade rule (availableKubernetesUpgrades and the UpdateCluster check) is not stated by the Oracle control plane upgrade page (contengupgradingk8smasternode.htm), which requires only that every worker node is ready and every node pool and node version is compatible with the target; the emulator keeps the one-minor limit.
- ListPodShapes returns only the four published pod shape names; the OCPU, memory and network bandwidth options per shape are not published (contengimagesshapes.htm lists names only), so they are omitted rather than invented.
- The virtual node pool size bound of 1000 is the node pool cap; Oracle publishes only the per-region virtual node limit (9 or 3), which is enforced as well.
- The emulator tenancy is an Oracle Universal Credits tenancy in a commercial realm; the Pay As You Go and trial limits (1 cluster, 3 virtual nodes) are not applied. Pods per managed node (256) and per virtual node (1000) are not enforced because no pods are scheduled.
- Essential add-ons (CoreDNS, kube-proxy, the CNI plugin) are not pre-installed on enhanced clusters: the add-on pages do not say which add-ons are installed by default.
- Add-on API names are matched case- and punctuation-insensitively against the display names of the Oracle add-on table, the only names the documentation publishes. Unknown configuration keys are accepted; the documentation does not say they are rejected. addonSchemaVersion, addonGroup and add-on level descriptions are not published and are omitted.
- The 30 day default rollback deadline of a public API endpoint decommission, and the absence of a work request on workload mapping changes, follow the SDK comments; the SDK does not document operation types for workload mapping changes.
- openIdConnectDiscovery is stored; the discovery endpoint and key are assigned by Oracle with an unpublished format and are not populated.
- vcnHostnameEndpoint and the VCN_HOSTNAME kubeconfig endpoint are never populated: the FQDN format is not published (contengnetworkconfig.htm).
- DeleteWorkRequest marks a work request CANCELED. Oracle does not say when work starts, so the emulator treats work as started once accepted and a finished work request answers 409.
- List ordering defaults (newest first), the cascade deletion of node pools with their cluster, whether DELETED resources are listed by default, and the DeleteNode work request operation type (NODEPOOL_UPDATE) are not published (checked the containerengine SDK request docs and contengoverview.htm).
- Nodes turn ACTIVE on the transition clock, not when the Kubernetes node reports Ready.
- Node cycling replaces every out-of-date node at once; maximumSurge and maximumUnavailable are validated but the pacing is not published.

## External effects that are recorded, not performed

- Credential rotation with the docker engine cannot regenerate the k3s serving certificates and admin token of a running container; the rotation state machine runs, the kubeconfig credentials stay, and the would-be rotation is logged.
- Kubeconfigs carry a static bearer token instead of the `oci ce cluster generate-token` exec plugin: the plugin signs a request to Oracle IAM, which an emulated API server cannot verify.
- Without OKE_ENGINE=docker the API server endpoints are documentation-range (or subnet CIDR) addresses nothing listens on, and worker nodes cannot register with a Kubernetes API.
- OpenID Connect token authentication settings are validated, stored and echoed; the k3s API server is not started with them.
- primaryVnic securityAttributes (Zero Trust Packet Routing labels) are stored and echoed; OCI Core has no ZPR policy engine to apply them.
- Node eviction settings (nodeEvictionNodePoolSettings) are validated and logged when a node is deleted ("would cordon and drain"); pods are not evicted.
